## 目标与现状

用户要求：全书与单话两条来源及清洗路径并存；翻译前必须通读 AI 版大合集并建立全书知识，另为当前话建立局部知识；译文须经独立审核、有限返工及通过门禁后才能发布；知识新增和修改先审核再生效。“全书”指某次采集时平台公开目录的完整快照，不含未公开或目录之外的内容；滚动采集不是同一时刻的原子快照。

## 职责与顺序

1. **采集**：发现作品与公开目录、获取元数据及每话，保存原始响应和可见原文、来源/版本清单；完成校验后发布与该快照绑定的单话文件和原文合集。缺章、失败或未知字段必须报告，不能冒充完整。
2. **清洗**：依据同一已验证来源版本，分别生成每话 AI/人读版及对应 AI/人读合集；原始归档只读。先确定可追踪的片段变换，再组装合集，使逐话与合集采用同一 profile、相同版本和相同正文；整体清洗还包括合集元数据、目录及跨章节边界检查，不得跨话合并或删改原义。
3. **知识**：对 AI 合集完成覆盖整个公开快照的分批通读、跨批归并和候选提取；针对当前话及相关上下文单独构建局部候选，执行冲突检测和审核。全书通读及批准知识发布为任何单话翻译的必要前置；当前话局部知识批准为该话翻译前置。
4. **翻译**：读取当前 AI 单话和已批准且版本匹配的全书、卷、章、话及相关实体知识，构建可审计的动态上下文；生成草稿、校对、润色版本。新发现只能形成带证据的知识候选，不能直接写入正式知识。
5. **终审**：独立审核最终候选译文，未通过则反馈问题并返工、重审；通过且来源和知识版本仍有效后才发布至 `熟肉`。失败或不确定结果不得伪装为通过。

Agent 是职责边界而非必须独立进程：采集/清洗可由确定性程序承担；知识抽取 Agent、知识审核 AI、翻译 Agent、终审 Agent 及必要时人工各有明确输入和输出。知识审核 AI 按既定风险分层与升级规则工作，高风险或证据不足时进入人工队列。终审逻辑与生成阶段独立；是否采用不同模型须评测，不假定换模型即可靠。

## 文件版本与合集契约

以下为建议布局；实际项目可继续使用 `workflow_paths.json` 指定外部人读版和译文根，不迁移或覆盖现有文件：

```text
projects/<work>/
  SourceArchive/collections/<snapshot_id>/raw-book.json
  RAWs_AI/chapters/<group>/episodes/<position>_<episode_id>.md
  RAWs_AI/collections/<snapshot_id>/book-ai.json
  RAWs_AI/catalog.json
  生肉/<章节名>/<话名>.md
  生肉/collections/<snapshot_id>/book-human.md
  生肉/SOURCE_MAP.json
  Knowledge/{candidates,reviews,published,snapshots}/
  Workflow/Runs/<run_id>/          # 草稿、审核、返工及恢复记录
  Workflow/{Plans,Approvals}/
  熟肉/                            # 仅终审通过的最终版本
```

`snapshot_id` 建议为目录、元数据及逐话来源版本集合的内容摘要；`run_id` 标识处理任务。人读文件名的 Windows 非法字符、同名与路径长度问题使用稳定 ID/后缀处理，不得凭名称猜测来源。

**原文大合集**建议为自包含 UTF-8 `raw-book.json`：包含 `schema_version`、`work_id`、来源 URL、采集起止时间、catalog/manifest 摘要、`snapshot_id`、完整性状态、全部已获取作品元数据及字段来源/缺失状态、按顺序排列的 `groups[]` 和 `episodes[]`。每话含稳定 ID、位置、卷/章标识及标题、URL、raw/HTML 版本 ID 与摘要、可见原文全文。HTML 原始响应留在归档中并由版本/哈希引用；JSON 文本解码后的 UTF-8 摘要须等于对应 `raw_source`。平台未提供或解析器未支持的字段标为未知并报告，不能编造或声称已获取全部可能字段。

**AI 大合集**建议使用同结构 `book-ai.json`，保留全部元数据、目录及逐话正文，增加 `profile_id`、父 raw 合集和逐话版本/摘要、输出摘要与转换报告。知识抽取有界流式读取该文件，每话及段落带稳定 ID 和源跨度；“通读”要求覆盖全部段落并进行跨批综合，不要求一次模型请求装下全书。

**人读大合集**建议为 `book-human.md`，包含可阅读元数据、目录和按章/话呈现的正文，并在文件内附机器可读版本/来源映射；正文分隔符冲突需转义且可追溯，渲染器不得静默吞掉正文。两种合集都须自带还原顺序、身份、来源和元数据的必要信息；额外索引仅用于加速。两版合集逐话内容须与各自单话文件及索引交叉校验；缺项或映射不唯一时拒绝完成。

**更新**：目录、元数据、任一 raw 版本或清洗 profile 变化形成新快照和合集版本，旧版本保留；输入身份与内容相同则幂等复用。新增话先生成两版单话再形成完整新合集；修改、删除、重排和元数据变动分别报告 diff，无法证明身份/顺序时停止。来源更新标记关联知识、翻译和审核过期，不覆盖旧成果。版本按用户既定决策保留至显式删除。

## 知识模型与审核

正式知识建议记录稳定 `knowledge_id`、不可变 `revision_id`、作品 ID、范围（书/卷/章/话/场景及稳定 ID）、类型、结构化内容、别名/关系、语言、状态、冲突组、更新时间、创建方式和置信度。证据至少包含合集/单话版本、episode ID、段落或字符跨度、证据原文或受控本地引用、证据哈希及采集时间；没有来源或证据不足的推论只能作为不确定候选。置信度是审核参考，不是自动批准依据。原文证据、日志和外发遵守已授权 Provider/类别及最小披露。

知识类型覆盖：Tag、题材、内容定位；文风、叙事视角与语气；双语词汇、固定译法与禁译；专名、表达、俚语、文化注释；人物身份、别名、称谓、性格、口癖及关系；世界观、时代、地点、组织和势力；主支线、人物事件链、时间线、地点线及因果；伏笔与回收、前后照应、歧义；敏感点、章节/场景摘要及其他翻译约束。卷信息缺失时标未知，不凭话号猜测；动态关系与剧情应有生效范围，避免后文信息误用到前文。

候选状态建议为 `candidate -> review_pending -> approved | rejected | needs_revision`；修改已批准项时产生新候选 revision，不原地覆盖正式版本。审核 AI 核验来源、冲突及风险；人物/剧情等高风险事实逐条批准，术语候选先审核，低风险 TM 使用门禁与抽查；不确定或冲突升级人工。批准后发布不可变知识快照，记录审核对象版本、决定、理由、责任人或 AI 标识、时间和旧新版本关联；本地未签名回执不能证明身份或语义正确。

翻译中发现的新知识进入候选队列，不能静默生效。若候选影响当前话，暂停待审或仅继续为未发布草稿，并在批准后重审；未批准候选不得作为固定事实。来源更新、知识冲突/撤回时先标记受影响知识、译文和审核过期，再复核并发布新版本。

## 翻译终审与发布

翻译输入绑定 `snapshot_id`、AI 合集/单话版本和哈希、待译段落 ID、批准知识快照及实际使用的全书/卷/章/话/实体知识 ID、提示词/profile、模型与授权范围。检索须记录实际命中项和摘要；必要知识缺失、未批准或版本过期时停止或转人工，不静默降级。上下文不足时分段处理、保留必需术语与证据并记录覆盖，不得跳过全书通读门禁。

每次草稿与返工形成不可变版本：`run_id`、话 ID、来源/知识版本、尝试号、父译文、输出哈希、模型/配置摘要、时间和状态。中间结果位于 `Workflow/Runs`，不得写入 `熟肉`；TM 和知识更新先作为候选。正式发布绑定最终译文、终审报告、来源及知识快照；提交前复核哈希和审批，以恢复日志实现提交/对账，并拒绝覆盖冲突文件。现有单写入者恢复可作起点，不假定已支持多文件原子事务、多进程或断电恢复。

终审输入为原文、最终候选译文、相关已批准知识、章节上下文与格式契约。报告至少包含 `review_id`、各输入版本、`pass|fail`、分维度及总评分、评分规则版本、问题列表（严重程度、类别、原译段落/证据、原因、建议）、审核者/模型标识与时间。检查忠实完整、语义、人物称谓/口癖、术语、文风可读性、剧情逻辑、章节格式、敏感点与明显事实错误；内容拦截须报告，不能通过回退绕过。

通过前必须定义可配置、可复核的严重度及分维度门槛；忠实度、完整性和关键事实设硬门槛，总分不能抵消严重问题。无效报告、缺少证据、超时或输入版本变化均为未通过或待人工处理。建议初始最多 **2 次返工**（初审后最多两次修订与重审），实际门槛和次数实施前确认；耗尽、反复严重错误、模型拦截或冲突时保留所有版本并标记 `needs_human`。人工修订后重新审核；例外发布策略需另行决定，本方案不设静默例外。

## 失败与恢复

| 情况 | 处理 |
| --- | --- |
| 限流、超时、临时不可用 | 授权范围内有限重试和退避；仅对已选择且单独授权的备用 Provider 有限回退，记录尝试及可能重复计费；内容拦截不触发绕过。 |
| 缺章、目录变化、采集暂停 | 保留 checkpoint/版本并报告，禁止生成标为完整的合集或进入全书知识门禁；恢复前重验目录和已完成来源版本。 |
| 清洗失败、未知标记、映射不一致 | 保留原始内容及失败详情；无法安全转换的标记保留并报告，无法证明边界/一致性时暂停发布，不覆盖旧产物。 |
| 模型上下文/单段预算不足 | 用匹配模型的 tokenizer 分批，记录每段覆盖后跨批综合审核；单段超限设计可逆分片或转人工，不能静默截断。 |
| 知识缺失、冲突或过期 | 标记状态，重新提取并审核；相关章节阻塞或待人工，不能将未批准信息当成当前事实。 |
| 审核失败、异常中断或提交冲突 | 中间结果只存任务区；有限重试后进入 `needs_human`。恢复前校验来源、知识、候选译文、审核及提交日志，不重复发布或覆盖用户文件。 |
| 发布后更正或撤销 | 保留原版本与审计，发布更正版本；分别记录本地及已授权远端副本处置结果，失败留待重试。 |

## 实施工作包

每项先用合成 fixture；真实作品、端点及外发范围分别按既有授权执行，mock 不代替真实质量验收。

| 顺序及映射 | 目标与任务 | 前置、交付及验收 | 风险 |
