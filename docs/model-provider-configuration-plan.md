# 模型与 API 配置方案

## 2026-11-20 API 池配置

`部分实现` `scripts/configure_api_pool.py` 在运行现有 Kakuyomu 编排器前交互登记多个 OpenAI-compatible 生成端点、模型 ID 和 Key，为初译、校对/知识抽取、润色分配端点，并可选择一个独立备用端点。可选配置 `FINAL_REVIEW_MODEL`，要求其规范化端点与实际模型 ID 均不同于初译和校对/返工路由；`scripts/review_translation_candidate.py` 可显式执行绑定策略的双次评估，`scripts/run_ai_translation_workflow.py` 可显式执行有限的 finding 定向返工、复审及通过后发布。返工复用 `PROOFREAD_MODEL`，授权 `source_text` 与 `translation_text`；终审模型需获准接收三类翻译数据。该路径只经合成测试，不证明模型质量、语义独立或实际修订效果。现可另行选择 Gemini 或 OpenAI-compatible embedding endpoint/model/Key，并在读取 Key 前单独确认该 Provider 接收 `source_text`。各职责说明能力需求，不声称模型性能已验证。缺少端点、模型、Key 或所需授权时无法执行相关远端调用。

使用 `python scripts/configure_api_pool.py -- <run_kakuyomu_workflow.py 的参数>`；知识候选抽取可使用 `python scripts/configure_api_pool.py --knowledge -- <auto_extract_knowledge.py 的参数>`。其余参数及计划/知识/发布门禁仍由既有入口处理。无参数可配置并选择保存，但不会启动翻译。

当前三个流水线生成绑定按代码实际映射为：`INITIAL_MODEL` 负责初译及反思重译；`PROOFREAD_MODEL` 负责上下文标注、校对和全书/单话知识抽取；`STYLE_MODEL` 负责润色。`FINAL_REVIEW_MODEL` 经静态预检后可由终审 CLI 调用；两次评估走相同 route，不构成独立身份或语义正确性证明。终审预检要求接收方获得 `source_text`、`translation_text`、`book_knowledge` 全类别授权；当前审阅 prompt 实际发送 source、translation 和策略定义，不发送 book knowledge。向导会在读取 Key 前显示并确认接收类别。向导只为已分配职责索取端点 Key，不保存未分配端点；激活 API 池时清除旧池 Key 和未配置的 `FINAL_REVIEW_MODEL` 环境变量。

`部分实现` 用户选择保存时，生成池和可选 embedding 配置写入当前用户 `%LOCALAPPDATA%\TranslatorAI\api-pool.json`；Key 保存在当前用户 Windows Credential Manager 中，profile 只存凭据引用及授权。凭据绑定整份配置摘要，配置变更导致绑定不符时拒绝加载；运行期间 Key 进入当前进程环境，可能被子进程继承。配置保存失败时只回收本次已成功写入的新凭据引用，不触碰旧配置/凭据；若清理本身失败，会报告需检查 `TranslatorAI/API` 或 `TranslatorAI/Embedding` 项。schema v1/v2 可加载；确认迁移的 v1 仍迁到 v2。新配置无终审槽时保存为 v2，配置终审槽时保存为 v3；两版 embedding 字段保持兼容。新旧凭据引用均不自动删除。存储依赖 Windows 用户账户及凭据服务，换账户或设备需重新配置；同一账户内运行的程序仍可能访问其凭据。真实端点诊断和真实服务验收仍为计划。不要把真实 Key 放入命令行或聊天。

配置时逐端点明示并确认本次职责所需 `source_text`、`translation_text` 和 `book_knowledge` 类别；备用端点同样须授权。备用仅对连接错误、408/429 和 5xx 尝试一次；内容拦截和认证错误不触发，可能重复计费。当前备用仅覆盖 `UnifiedAgent` 翻译调用，不覆盖独立知识抽取脚本；后者沿用校对模型的主端点。Key、端点、模型兼容性和真实质量未作线上验证。

- API 池增量（R4 前快照）本地验证：`tests.test_api_pool` 11 项通过；`tests.test_api_pool tests.test_pipeline_contracts tests.test_kakuyomu_workflow -q` 164 项通过；当时全量非 E2E 677 项运行、673 项通过、4 项跳过；loopback mock E2E 7 项通过。覆盖生成请求模型 ID、启动预检、未使用端点不取 Key、凭据写入/配置替换失败回滚、主备授权及内容拦截不回退。当前 schema v2、embedding 与迁移验证见[最新开发记录](development.md#2026-11-20-api-池-v2-与可配置-embedding)。测试不访问真实 Provider，不验证渠道兼容、账单或语义质量。

## 2026-11-20 职责细分与统一嵌入规划

本节是**后续实施计划**，不是已上线能力，也不是另一份总路线图；工作包对应下方 M1–M6 和[项目路线图](roadmap.md)阶段 0–3。复核基准为分支 `codex/translation-workflow-audit-20261117` 的 HEAD `9374fa7` 及当时未提交工作树。本轮未读取私有配置、Key 或书籍正文，也未调用外部服务。

本节记录的是 Provider 配置与职责拆分工作包。K4 双次终审和显式 AI 返工/复审 CLI 已在后续增量落地，当前事实以[翻译流程](translation-workflow.md#ai-终审与发布)、[项目现状](project-status.md#2026-11-20-k4-自动返工与复审)和[最新开发记录](development.md#2026-11-20-k4-ai-返工续审工作流)为准；本文的 M/R 计划不代表 K4 整体验收完成。

### 现状、证据与边界

- `部分实现` 当前向导有三个生成绑定，现已按调用映射显示：上下文标注、校对、知识抽取及定向返工使用 `PROOFREAD_MODEL`，初译和反思重译使用 `INITIAL_MODEL`，润色使用 `STYLE_MODEL`。此处仍是三个共享绑定，不代表各职责已有独立 Agent。AI reviewer/返工 CLI 已实现，但不在初译中自动触发。分别见[向导](../scripts/configure_api_pool.py)、[流水线](../pipeline.py)、[知识抽取](../scripts/auto_extract_knowledge.py)与[翻译流程](translation-workflow.md#ai-终审与发布)。
- `部分实现` [向导](../scripts/configure_api_pool.py)的 `activate` 用池内授权替换当前进程 `PROVIDER_DATA_POLICY`；池条目包含 OpenAI 兼容生成模型及可选的独立 Gemini/OpenAI-compatible embedding 绑定。RAG 与[章节对齐](../scripts/align_chapters.py)共用 [embedding 适配器](../embedding_provider.py)，TM 新向量带有 schema、Provider、协议、模型、task type 和维度身份；OpenAI-compatible 身份还绑定 endpoint 摘要。检索及章节语义回退忽略无身份或身份不匹配的旧向量；旧 TM 尚未重嵌入。查询 embedding 失败会阻止章节处理，TM 更新失败会整体中止；旧向量造成的空结果是隔离状态，不是语义检索成功的证明。
- `部分实现` [API 池存储](../api_pool_store.py)按配置内容保存 schema v2 或 v3：v2 支持三个既有生成职责和可选 embedding Provider；可选终审角色进入 v3。v1/v2 均可加载，只有操作者明确确认后才备份并把 v1 迁移到 v2。配置摘要与 Windows Credential Manager 凭据绑定；直接修改保存的 JSON 会使凭据绑定校验失败。旧环境变量、显式 JSON 和池入口并存，不能假定自动共享会话授权。
- `已验证` 本轮只读环境检查显示 Windows、项目 `.venv` 的 Python 3.14.7，且可定位 `openai`、`google.genai`、`numpy`；这只说明模块可发现，不证明依赖完整、服务部署、网络、API Key、协议或模型可用。用户报告已通过向导配置 `jojo_code` 供测试；本轮未检查该私有配置，不推断实际值或连通性。
- `未知` 真实端点和渠道对生成/嵌入协议的兼容性、可用模型 ID、上下文和 tokenizer、调用额度、敏感文本政策、故障率、真实费用及翻译质量；实施时由开发者用合成数据和明确触发的获准样本分别核实。需求中的 `GLM-5.3-Flash`、`Qwen3.8-Flash` 暂记用户提供名称，不推定官方 ID 或适用性。

### 统一配置与兼容方案

1. `计划` 在同一配置流程中管理 Provider、生成模型、嵌入模型、职责绑定、备用策略、凭据引用及每个接收方的数据类别；生成与嵌入可共享或分别使用端点和 Key，但不得把 embedding 模型作为生成模型。展示模型、协议、端点与实际接收方；自定义 URL 验证沿用 HTTPS/loopback 规则。
2. `计划` 先定义 Gemini SDK 适配边界并验证现有模型路径，再以合成服务验证候选 OpenAI 兼容 embeddings 接口；模型 ID、批次、向量维度与返回格式以对应渠道契约和实测为准，不假定所有“兼容”接口相同。Provider 不支持目标协议时明确报错。
3. `计划` 将各已启用职责和备用调用需要的数据类别按 Provider 合并；保留已有授权并预检本次请求，不能因启用嵌入覆盖生成授权，也不能静默授予无关用途。内容拦截不触发回退；连接、超时、408/429、5xx 的有限回退与重复计费风险继续单独呈现。
4. `计划` 定义版本化配置迁移：只读验证 v1、准备非秘密备份，读取现有凭据引用并为新配置重新绑定摘要，完整写入和验证后原子切换；任一步失败保留旧配置、旧凭据和可恢复入口，不自动删除凭据或要求用户重输既有 Key。仅新添嵌入 Provider 缺少凭据时由用户在安全入口提供。测试须覆盖中断、缺失凭据、绑定不符和重启回滚。
5. `计划` 为存储的向量记录 Provider/模型、版本或渠道身份、维度及生成参数；来源、身份或参数不兼容时拒绝混用，并显式标记需要重建或安全降级。旧 TM 无向量身份时不因维度相等而默认兼容；先隔离/保留原数据，在获准原文及可用模型条件下重建、核验后切换。TM 检索、TM 写入和章节对齐的向量生成均须接入同一身份契约。
6. `计划` 验证配置只做静态诊断；真实连通性测试须由用户明确触发，先使用合成内容并显示可能产生的费用。保存后可重启加载；避免 Key/完整请求头/书籍正文写入日志、配置或错误报告。真实服务、内容审核与语义质量各自留存独立验证结果。

## API 配置与人机交互方案

### 配置页面/命令流程

当前仓库已有生成 API 池和 embedding 绑定的交互式 CLI，以及环境变量/JSON 配置；K4 终审角色可选配置。以下完整界面流程仍属`计划`，不代表已存在 Provider 连通性诊断、用量面板或 Web UI。建议先扩展 CLI 配置管理/诊断，再依据用户交互需求决定是否开发桌面或 Web UI。

1. **Provider 端点与凭据**：新增/编辑 Provider，填写显示名、协议类型、API URL、可选 API 版本和 Key；Key 输入后显示脱敏状态。自定义 OpenAI-compatible URL 与 Gemini 专用 API URL 应由不同协议类型承载。
2. **模型目录**：添加模型 ID、能力类型（文本生成、封闭决策、嵌入）、所属 Provider、上下文/输出约束（仅在可确认时）、价格来源/更新时间、用户自定义别名。模型类型不匹配时不得被阶段选择器接受。
3. **阶段职责分配**：按职责显示首选模型、备用模型、禁用/仅手动选项；展示来源标签（官方能力、用户渠道价、尚未验证）和切换影响。Embedding 只可分配到嵌入任务，Decision 仅可分配到封闭决策任务。
4. **验证连接**：用户明确触发后发送最小、非书籍内容的测试请求；显示 DNS/TLS/HTTP 状态、鉴权错误、端点不兼容、模型不可用、限流/配额和超时分类。不得在每次保存时自动调用付费 API。
5. **用量/配额**：显示用户录入的参考上限与 API 响应观测到的实际 429/限流信息，分开标注；以每日/每分钟限制、并发/速率状态提示暂停或降速。
6. **保存与回滚**：保存前做配置校验和差异预览；更改首选模型不自动重新处理已完成章节。允许恢复上一个有效配置版本，不保存秘密明文版本。

### 配置数据结构建议（非代码草案）

配置存储按职责拆分以下逻辑对象；实际序列化格式和迁移方式须在阶段 1 确认：

| 对象 | 建议字段 | 敏感性/规则 |
| --- | --- | --- |
| Provider | 稳定 ID、显示名、协议/适配器、API base URL、认证方式、超时、启用状态 | URL 不含 Key；支持自定义端点但限制 URL scheme。 |
| Credential reference | Provider ID、Windows Credential Manager 项标识、Key 最后更新时间/脱敏提示 | 仅引用系统凭据存储，不把 Key 放入 JSON、环境快照、日志、崩溃报告或 Git。 |
| Model | Provider ID、API model ID、显示名/别名、能力类型、用户录入价格、价格币种/单位/来源/更新时间、参考配额 | 未知字段显式为未知；不要由别名推导模型能力。 |
| Stage binding | 阶段 ID、任务类型、primary model ref、fallback model refs、数据授权标签、最大重试/超时、是否启用 | 校验能力匹配、回退协议及输入数据授权。 |
| Usage observation | 日期、Provider/模型、请求/输入/输出/缓存 token、HTTP 状态、限流头/重试提示、估算费用 | 不记录 Key、原文/译文正文；用量以 API 实际返回为准，缺字段为未知。 |

### 安全、校验与故障语义

- Windows 首选 Windows Credential Manager；如未来支持其他 OS，使用对应系统密钥库。禁止将 API Key 明文写入项目 JSON、`.env.example`、日志、命令历史或错误消息；`.env` 仅作为当前兼容开发方式，安全约束见[本地凭据风险记录](security-notes.md)。
- URL 校验要求 scheme、host、端口、路径格式合法；公网 Provider 默认要求 HTTPS。允许 HTTP 仅限显式批准的 loopback 本地服务，并阻止无提示的明文远端请求。当前 OpenAI-compatible 客户端关闭自动重定向，要求配置规范 URL；若后续需要重定向支持，须确保不同 origin 时不携带认证头并增加回归测试。
- 配置校验包含：必需字段、Provider 协议、凭据可用性、model ID、模型能力、生成/嵌入/决策协议匹配、超时与重试范围、主备模型组合和数据授权约束。
- 错误分类至少区分本地配置错误、网络/DNS/TLS、401/403 鉴权/权限、404 模型/路径、400 请求/schema、429 限流/配额、余额/计费限制、5xx 服务端、超时及内容拦截。错误提示提供可操作修复线索，不回显密钥或完整请求头。
- 回退策略需显式配置、有限重试并记录模型切换原因。可对暂时网络错误、429 和部分 5xx 执行受限重试；鉴权失败、错误模型 ID、协议/schema 错误和内容拦截不应盲目重试。跨供应商回退可能重复计费、改变模型行为和发送数据给另一服务商，执行前需逐 Provider 授权。内容拦截仍遵循当前项目终止边界，不通过切换模型规避。
- Gemini 配额不可用静态表格硬编码为账户保证值；用户数字作为带时间戳的参考值，运行时受限作为另一个观测。DeepSeek 时段费用按供应商 UTC 规则计算，并在界面显示用户所在地时区。
- 评估配置导入/导出时，默认排除凭据值。支持用户显式清除凭据引用；不自动撤销服务商 Key。

### 既有配置与路由基线

以下保留已有路由和历史验证边界；2026-11-20 新增的 API 池见上节，不改变这些旧路由的默认行为。

- `pipeline.py::get_primary_provider_route` 集中依据模型名把 `sakura`/`sakura-`/`qwen3.6-plus` 路由到 `SAKURA_BASE_URL` 与 `SAKURA_API_KEY`，把 `gpt-6-luna*` 路由到 JOJO，把精确的 `deepseek-v4.1-flash` 路由到 JYQF，其余 `deepseek-` 路由到 DeepSeek；空白、首尾带空格和不受支持的名称会在章节扫描/客户端创建前拒绝。调用请求与启动 Key 检查共用此映射。该防误路由校验不构成通用 Provider/模型目录或阶段能力配置。
- OpenAI-compatible base URL 在流水线预检和客户端创建处校验：只接受有主机名和有效端口语法的 HTTP(S) URL；公网必须 HTTPS，HTTP 仅限 loopback；拒绝 URL 内认证信息、查询和片段。API Key 继续通过 Provider 专属配置读取。SDK 自动重定向关闭，端点必须提供规范 URL。
- 已修复 `get_base_url` 曾在通用 `CODING_PLAN_BASE_URL` 配置为 loopback 地址或带显式端口 URL 时覆盖上述已选择端点的问题。仓库声明的默认 DashScope URL 没有显式端口；回归测试使用带显式端口的配置复现旧覆盖行为。当前仅测试环境显式设置 `MOCK_SERVER_PORT` 时覆盖为本地 mock URL。
- 当前显式 Gemini 回退仅允许 SDK 连接/超时异常及 HTTP 408/429/5xx；鉴权、请求/schema 错误和内容拦截不触发回退。该本地错误边界由单测和 mock E2E 验证，不构成 Provider 配置、逐阶段绑定、逐数据类别授权或真实服务兼容性验收。
- JOJO→JYQF 回退由 `ENABLE_JYQF_FALLBACK` 显式启用，默认关闭，只覆盖 JOJO 主路由；使用 `deepseek-v4.1-flash`，复用同一请求提示词与响应 schema，备用客户端设置 `max_retries=0`，避免 SDK 在单次回退调用内自动重试。阶段启动预检会校验 JYQF URL、数据类别授权和远端 Key；`UnifiedAgent` 创建 JYQF 客户端前再次检查类别，本地 loopback 按本地端点规则处理。回退失败会直接传播，不级联 Gemini。仅有合成契约测试证据，mock E2E 不覆盖该回退路径；真实中转站兼容性、费用与模型表现未验证。
- `API_TIMEOUT` 默认 10 秒且必须是有限正数；当前传入 OpenAI-compatible 聊天和 Gemini 生成、RAG embedding、章节对齐 embedding 调用。Gemini SDK `HttpOptions.timeout` 使用毫秒，由秒值换算；默认值对慢速模型可能过短，须按获准端点实测后由操作者配置。
- `PROVIDER_DATA_POLICY` 已实现为默认空的逐 Provider/数据类别 allowlist，涵盖主请求、Gemini 回退、RAG、章节对齐和知识抽取。生成流水线按阶段声明最小类别；启动预检只检查当前运行时可达的 Gemini 回退阶段，并逐阶段检查 JOJO→JYQF 回退与实际调用一致。类别未全部获准时请求在客户端边界被拒绝。2026-11-17 的历史记录中本机 `.env` 为试点列出 `source_text`、`translation_text`、`book_knowledge`；当前私有配置未在本轮核验。用户后续同意 AI 模型履职所需数据，代码默认仍为空；真实端点和实际请求尚未验收。
- 2026-11-17 配置增量：`Config.load_config` 允许 `INITIAL_MODEL`、`PROOFREAD_MODEL`、`STYLE_MODEL` 由环境变量覆盖 JSON 配置；本机试点用例选择 JOJO 主模型并启用已选 JYQF 有限回退。回归覆盖环境变量优先级。配置系统仍未提供一般化 Provider/模型能力目录、阶段 UI、凭据存储或端点验证命令。
- 知识抽取脚本使用 `Config.PROOFREAD_MODEL` 发起请求，并复用 `get_primary_provider_route` 选择对应 Provider ID、base URL 与专属 Key；未知模型名在读取来源前失败，避免模型 ID 与实际接收 Provider 不一致。该共用路由不自动授权知识抽取用途，仍须该 Provider 的 `source_text` 在本地 allowlist 中获准；全书预算/分批与 tokenizer 适配未实现。
- `CODING_PLAN_BASE_URL`/`CODING_PLAN_API_KEY` 仍在配置类中声明/读取，但没有接入当前主请求路由。用户决定暂不作为独立 Provider 支持，保留未接入配置；不能据此声称已实现 Coding Plan 或可替换 Provider。
- 以上是静态代码与 mock 测试基线；本轮未调用真实端点。M1 仍须定义完整 Provider/模型/凭据/阶段绑定契约，并为当前真实配置建立迁移和兼容规则。

### M6 评测最低规范

- 用户选择按职责分别设定质量门槛，不以单一总分代替所有阶段；具体门槛、预算和默认模型需结合获准样本评测后确定。
- 先明确质量门槛，再评模型；忠实度错误严重度高于流畅度优化。逐章记录模型版本、Provider、提示词版本、参数、数据授权和参考知识快照。
- 对比时固定输入、上下文、温度/推理选项（若协议支持）、段落边界和重试策略；记录失败/拒答，不把失败样本从统计中删去。
- 单价最低但人工修订显著增加的配置，不得仅凭 API 账单判为最优；总成本应包括多阶段调用、回退/重试、嵌入和人工后编辑时间。
- 评测样本及输出留在获准的本地项目存储；外发或上传评测集前须按项目数据政策取得授权。
