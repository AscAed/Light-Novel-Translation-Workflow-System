# 项目现状

> 状态基准：2026-11-13。证据范围：当前工作区文件、Git 状态、静态配置检查及本轮验证。状态不是生产部署声明。

## 已实现

- `pipeline.py`：Python CLI；按章节读取 Markdown，构建上下文，依次执行上下文标注、初译、校对、润色，并写入译文和翻译记忆。
- `rag_engine.py`：翻译记忆向量检索、术语匹配、分章指导检索及记忆写入。
- `scripts/align_chapters.py`：双语章节段落对齐、对齐结果向量化并写入翻译记忆。
- `scripts/auto_extract_knowledge.py`：从最多前三章生成术语表和概要草稿；这是实验脚本，不等同于审核/发布流程。
- `prompts/`：初译、逻辑校对和文风润色提示词。
- `tests/`：标准库 `unittest` 测试、独立 mock HTTP 服务、RAG/对齐/路径安全测试。
- `projects/example/`：小型示例原文、译文和书籍知识样例；不代表实际运行产物或真实书籍数据。

## 部分实现与差距

- `部分实现` 多 Agent：当前由单进程按阶段调用多个模型端点；未发现独立 Agent 运行时、队列、调度器、持久化任务状态或用户交互界面。
- `部分实现` 翻译记忆：使用 JSON 文件和嵌入向量；自动写入，但缺少审核、版本、来源追踪和冲突治理。
- `部分实现` 章节格式保护：翻译阶段对段落数量错配 fail-fast，校对结果错配时保留上一版对齐译文；日文引号配对与最终文本质量仍未成为统一硬门禁。
- `部分实现` API 容错：Gemini 故障转移默认关闭；显式开启后主端点普通异常才会触发。内容拦截不会触发跨 Provider 回退。
- `部分实现` 路径边界：章节直接文件拒绝符号链接，译文采用排他新建；显式配置路径仍由操作者负责，平台级并发链接竞态未完全封闭。
- `部分实现` 配置：支持环境变量、项目目录及 JSON 配置路径；有基础 `requirements.txt`，但依赖未锁定，也没有完整部署配置。
